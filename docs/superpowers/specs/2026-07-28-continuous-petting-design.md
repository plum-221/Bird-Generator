# 小鸟持续抚摸设计

## 目标

把现有“一次滑动触发一次表情”升级为持续抚摸：用户按住小鸟来回滑动时，模型连续表现出享受或害羞反应；停止后平滑恢复。

## 交互规则

- 鼠标和单指触摸共用同一套距离与时间判断。
- 按下后累计有效移动距离；只有持续移动才维持抚摸，按住不动不重复触发。
- 达到现有滑动门槛后进入持续抚摸，移动期间刷新维持时间；松手或停止移动约半秒后退出。
- 一次连续手势只在开始时显示台词；爱心或害羞符号低频出现，不随每个移动事件刷屏。
- 连续抚摸不计入快速多次触碰的“逗弄”升级，避免正常抚摸误触发生气。

## 分区反馈

- 头部：持续眯眼，头部轻微朝抚摸方向倾斜，偶尔出现爱心。
- 胸部：害羞低头，身体轻微起伏，偶尔出现害羞线。
- 身体：羽毛逐渐蓬松，翅膀稍微放松，身体轻微起伏。
- 喙和翅膀继续沿用现有单次触碰语义，不进入持续抚摸。

## 状态与实现边界

- 在 `birdPetInteractions.js` 的手势跟踪器中增加持续抚摸采样，输出开始、维持和结束所需状态；不把计时散落到 DOM 层。
- `main.js` 只负责把指针移动输入交给手势跟踪器，并把采样结果送入现有表情控制器。
- `birdBuilder.js` 继续通过现有 `applyExpression` 接口表现模型动作，不新增第二套动画系统。
- Motion 模式保持既有安全边界：允许漫画符号和台词，不叠加软体抓取或持续模型变形。

## 验收标准

1. 头、胸、身体来回滑动可分别持续呈现对应反馈，松手或停手后平滑恢复。
2. 按住不动不会持续刷表情、符号或台词。
3. 一次长抚摸不会升级为生气；快速分开的多次触碰仍可触发逗弄。
4. 桌面鼠标与手机单指均通过，原有点击、托举、玩具和 Motion 模式不回归。
5. 自动测试、生产构建与浏览器视觉验收通过。
